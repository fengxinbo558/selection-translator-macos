# 跨桌面与全屏快捷窗口修复设计

## 目标

按全局快捷键后，划译窗口必须能出现在用户当前工作的界面，包括普通桌面、其他桌面 Space、其他应用的 macOS 全屏空间和外接显示器。

## 根因

当前窗口行为不一致：主输入窗口使用 `canJoinAllSpaces`，快捷结果、加载和提示窗口使用 `moveToActiveSpace`；所有窗口都缺少 macOS 15 面向跨应用全屏悬浮层的 `canJoinAllApplications`。部分窗口因此停留在原 Space，或被其他应用的全屏窗口遮住。

## 方案

1. 建立统一的窗口展示配置，应用到主输入、加载、快捷结果、普通提示和权限提示。
2. 所有划译窗口启用：
   - `canJoinAllSpaces`：可出现在所有桌面 Space；
   - `canJoinAllApplications`：可加入其他应用的全屏和 Stage Manager 空间；
   - `fullScreenAuxiliary`：作为全屏辅助窗口显示；
   - `transient`：不污染 Mission Control 的普通窗口排列。
3. 窗口层级使用 `.statusBar`，确保浮在普通应用和全屏应用内容之上，但不使用侵入性更强的屏保层级。
4. 每次显示前根据鼠标位置重新选择屏幕并计算窗口位置；外接屏幕上触发时显示在对应屏幕。
5. 需要输入的主窗口和权限提示会激活并取得键盘焦点；只展示进度或结果的快捷窗口不抢走原应用焦点。
6. 保持现有关闭规则和受保护内容规则不变。

## 不采用的方案

- 仅启用 `canJoinAllSpaces`：不能完整覆盖其他应用的全屏空间。
- 使用 `.screenSaver` 层级：可能遮挡系统安全界面和其他系统浮层，过于侵入。

## 验证

- 单元测试覆盖统一窗口行为配置的必需选项和层级。
- 普通桌面触发后能看到主输入或快捷结果窗口。
- 切换到另一个 Space 后触发，窗口出现在当前 Space，而不是原 Space。
- 其他应用进入 macOS 全屏后触发，窗口显示在该全屏空间上方。
- 外接显示器或不同屏幕位置触发时，窗口位于鼠标所在屏幕的可见范围。
- 连续翻译修复单独验证三次连续输入，确保本修复不掩盖翻译任务生命周期问题。
