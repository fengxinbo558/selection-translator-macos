# ⌘T 输入框与选区翻译修复设计

## 目标

修复两个直接影响使用的问题：主翻译窗口的中文输入区不够明确；按 ⌘T 在没有可读选区时错误地进入截图框选，让用户感觉快捷框失效。

## 已选方案

采用“⌘T 智能分流、截图快捷键独立”的方案：

1. 按 ⌘T 后，若成功读取到选中文字，继续自动翻译并按现有规则替换或展示译文。
2. 若没有选中文字、浏览器没有提供可读选区，或辅助功能权限尚未开启，直接打开主翻译窗口。
3. 主翻译窗口必须立即获得输入焦点，并清楚显示“输入中文”标题和可输入区域；同时允许输入英语、日语、韩语以执行反向翻译。
4. ⌘T 不再自动进入截图框选。截图翻译只由独立截图快捷键和“截图翻译”按钮触发。
5. 受保护内容仍按原有安全提示处理，不把它伪装成普通无选区。

## 备选方案与取舍

- 保留自动截图降级：浏览器覆盖范围高，但与“⌘T 调出可输入快捷框”的预期冲突，已放弃。
- ⌘T 永远打开主窗口：规则最简单，但会失去选中文字直接翻译的效率，已放弃。
- 智能分流（采用）：有选区时最快，无选区时始终有可输入的退路，截图功能也不会意外抢占流程。

## 界面

- 将模糊的“原文”改为“输入中文”。
- 辅助说明改为“也可以输入英语、日语或韩语，会自动翻译成中文”。
- 空状态仍显示当前方向，例如“中文 → 英语”。
- 打开主窗口时，光标直接位于输入区，用户可以立刻打字或粘贴。

## 错误处理

- `.noSelection` 和 `.accessibilityPermission`：打开空白主翻译窗口，不显示短暂错误框，不进入截图。
- `.protectedContent`：保留受保护内容提示。
- 其他实际错误：继续显示对应错误提示。

## 验证

- 单元测试覆盖选区错误的分流策略：无选区和无辅助权限进入输入框，受保护内容不进入。
- 界面实测主窗口显示明确输入区并能输入中文后得到英文。
- 实测 ⌘T 注册为 Command+T，读取不到选区时打开输入窗口。
- 实测独立截图按钮仍能打开框选层。
