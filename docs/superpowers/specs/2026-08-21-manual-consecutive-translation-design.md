# 手动输入连续翻译修复设计

## 问题

手动输入第一次可以快速翻译；修改为第二段文字后，界面一直显示“正在翻译”。此前通过复用同一个 `TranslationSession.Configuration` 并调用 `invalidate()` 触发下一轮，但系统翻译组件并不保证复用后的任务每次都会重新启动，因而仍会出现永久加载。

## 方案

1. 每一轮有效输入都结束旧的 `TranslationSession.Configuration`，先向 SwiftUI 发布空配置，再在下一次主界面更新中创建全新的配置，保证 `translationTask` 被重新挂载。
2. 翻译任务放在独立的后台承载视图中，并以请求编号作为视图身份；每次请求都会销毁旧任务承载视图并重新挂载，不重建输入框，不影响键盘焦点。
3. 如果用户在新会话启动前继续输入，取消待启动会话，只为最后一段文字创建会话。
4. 每次输入继续生成新的请求编号；旧任务即使晚返回，也不能覆盖当前输入的结果。
5. 保留现有 360ms 输入防抖，避免用户每敲一个字就启动一次翻译。
6. 输入清空时取消当前会话和待启动会话并回到空状态，不保留旧译文或加载状态。
7. 从配置发布开始计时；如果系统翻译任务根本没有启动，也会在超时后停止转圈并显示可重试错误。

## 不采用的方案

- 继续只调用旧配置的 `invalidate()`：真实界面已复现第二轮不启动，不能作为可靠方案。
- 强制重建整个 SwiftUI 视图：会重置焦点并可能产生闪动。
- 每次输入重开窗口：跳动明显且破坏连续输入体验。

## 验证

- 单元测试覆盖连续多次相同语言方向时先撤下旧配置，再生成全新配置。
- 单元测试覆盖快速连续改写时只有最后一次请求可以完成。
- 单元测试覆盖系统翻译任务没有启动时也能退出加载状态。
- 单元测试覆盖语言方向改变时创建正确的新目标配置。
- 真实界面连续输入至少三段不同中文，每一段都必须结束加载并显示对应英文。
- 清空输入后必须回到空状态，再次输入仍能翻译。
