# 英文缩写语言误判修复设计

## 问题

当前只有固定词库中已经收录的缩写会被强制识别为英语。未收录的短英文缩写仍交给系统语言识别器处理。短字符串缺少上下文，例如 `NL`、`JA`、`K8s`，系统可能把它们猜成荷兰语、日语等语言，进而弹出与用户内容无关的语言包下载窗口。

## 目标行为

- 纯 ASCII 英文字母、数字和常见技术分隔符组成的单个短词统一按英语处理。
- 支持大小写与技术写法，例如 `SLA`、`api`、`K8s`、`CI/CD`、`UTF-8`、`C++`、`C#`。
- 已收录缩写仍使用英文全称进行翻译，并提供中文含义和用途。
- 未收录缩写直接翻译原始文字；即使译文保持不变，也不得请求下载荷兰语、日语等无关语言包。
- 含中文、日文假名/汉字或韩文字符的内容继续交给正常语言识别，不受该规则影响。
- 手动输入、选中文字和截图翻译走同一规则。

## 识别规则

新增一个集中式的“英文技术短词”判断：

1. 去除首尾空白后长度为 2–32 个字符；
2. 至少包含一个 ASCII 英文字母；
3. 其余字符只能是 ASCII 字母、数字或 `. / - _ + # &`；
4. 不允许空格以及任何中日韩文字。

符合规则时，来源语言直接设为英语，不调用概率型语言识别器。32 字符上限避免把长串路径、密钥或其他非自然语言内容误当成缩写。

## 代码边界

- `SourceLanguageResolver`：提供可测试的英文技术短词判断，并在通用语言识别入口优先应用。
- `TranslationPanelModel`：手动输入和常规翻译配置前应用同一判断。
- `CompactTranslationModel`：选中文字与截图翻译配置前应用同一判断。
- `AbbreviationGlossary`：不改变固定知识库的职责；未知缩写不伪造全称或用途。

## 错误处理

本次修复只消除错误的源语言和语言包下载。未知缩写若没有可可靠确定的全称，仍按原字符翻译，不展示虚构解释。正常的翻译超时和“不支持语言”错误保持现有行为。

## 验证

- 单元测试验证 `NL`、`JA`、`K8s`、`CI/CD`、`UTF-8`、`C++`、`C#` 均判为英语。
- 单元测试验证 `GPUとは`、`AI是什么`、韩文内容不会被强制判为英语。
- 模型测试注入“荷兰语/日语”误判结果，确认未知缩写仍配置为英语来源、中文目标，且不会检查或准备无关语言包。
- 安装后实测连续输入未知缩写，确认不再出现截图中的语言下载窗口。
